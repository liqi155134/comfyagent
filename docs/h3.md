## SageAttention 乱码事故(已修复,2026-08-19)

**根因不是 sage 与 H3 不兼容,是 v2.2.0 tag 本身的 bug**(与 Modal 侧踩坑同源):
tag 带着 PR #218 的 sm90 wrapper —— custom op 往 out tensor 写结果却没声明
mutates_args,torch functionalization 把写入当 dead store 丢弃,拿到未初始化
显存 → patch 级马赛克,且日志全绿(上游 issue #288/#320)。

**修法:pin main 的 d1a57a546c3d**(2025-12-22 后已修)。同 seed 验收通过,
默认 USE_SAGE_ATTENTION=true。扩 sm89 卡时注意上游 setup.py 共享 NVCC_FLAGS
的缺陷(thu-ml#360):单架构编译会产出假 sm89 kernel,需 per-arch gencode
补丁 + cuobjdump 逐 .so 验证,并在启动侧做 compute_cap ∈ {8.9,9.0} 白名单门控。

教训:**管线通 ≠ 内容对**。换 attention/量化后端必须同 seed 抽帧看片 ——
速度、日志、退出码全都会骗人(坏版跑得也快,因为它确实在算,只是结果被丢)。

## i2v + sage 尾帧塌坏(2026-08-20 根因定论:Triton quant kernel int32 溢出)

> **根因(2026-08-20 实验闭环)**:`sageattention/triton/quant_per_thread.py` 的
> `quant_query_per_thread_int8_kernel` 用 int32 算行偏移 `offs_n * stride_in`。
> fused QKV 布局下 Q 的 seq-stride=21504,**行号 > 2^31/21504 ≈ 99865 时偏移
> wrap 成负数** → 有效行地址算错 → 读到垃圾(尾帧塌)或未映射页(illegal
> memory access,生产偶发的"宿主机瞬态"其实就是它)。K 因 `k-km` 物化为连续
> (stride=128)而幸免;contig 布局阈值 1670 万 token,永远安全。
>
> 证据链(H100 实测,scripts/diag_sage_tail.py v5):L=99840(阈值下)strided
> 与 contig 逐字节一致;L=99904(首个跨阈值)illegal access;L=101504(整除
> 128)照崩,排除尾块 remainder 论;**int64 补丁版 kernel(只改一行
> `offs_n.to(tl.int64)`)在 L=101509 strided 上与金标准逐字节一致 → 定论**。
> 另发现独立 bug:L%128==0 时 V 不 pad、strided 直进 per_channel_fp8 → crash。
>
> **推论:t2v 15s/0.9MP(L=100691)也已跨阈值**——尾部 826 行地址算错,当前
> "视觉干净"只是越界读恰好无害,不是安全。真正安全域:L ≤ 99864。
> 同族 Triton 上游:triton-lang/triton#6346、#9247。
> issue 草稿(已按定论重写):docs/sage-sm90-issue-draft.md,待用户确认后发。

**部署现状(2026-08-20 定论后)**:`h3` = `comfyagent-h3-sagefix`(h3-7 镜像,
启动链打 `scripts/patch_sage_int64.py`,补丁失败容器不起 → job 能跑 = 补丁生效),
t2v/i2v 默认;t2v 冒烟 39.3s、i2v 同 seed 全验证(258s,尾帧净)。`h3_ck` 保留作
高忠实度备选(首帧 MAD 1.77/255 vs sage 6.80,i2v 慢 ~49%)。旧 h3 端点(未修复
sage)已退役。上游合入 int64 修复后:去掉启动补丁、回归正式镜像即可。

以下为定位过程存档(其中"i2v conditioning 触发 / 尾块 remainder"等早期假设已被
上述定论取代,留作过程记录):

**现象**:h3_i2v(15s/1280×736)sage ON 时**最后 3-4 帧塌成灰色噪声**
(帧间差从 2-3 突跳到 88-93/255),前 470 帧完美;20 步与 8 步 LoRA 均复现。
同 seed 同参数 sage OFF 两格干净;**t2v 四格(含 sage ON)尾段全部干净**。
变量隔离结论:i2v 的 first_frame conditioning 是触发条件。

**上游线索**:ComfyUI #15263 —— H3 + sage 序列超 ~160k tokens 后超出部分
输出噪声(sm_120 全噪声版已在 0.31.1 修,我们 0.33.1 只剩尾部塌)。
机理吻合:i2v 比 t2v 多 conditioning tokens,序列尾部(=视频尾帧)跨过
kernel 坏区。thu-ml#325 / kijai KJNodes#712 同族。

**定位收口(2026-08-19 深夜)**:用户在 L20/sm89 环境独立踩过同族坑并修复
(comfy-kitchen 的 int8 kernel 对 size-1 维度 stride 误判,= 上游 PR #112,
已进 0.2.31)。但我们镜像里就是 0.2.31 仍塌 —— 读 ComfyUI 0.33.1 源码确认
`--use-sage-attention` 走 thu-ml wheel、`--use-ck-attention` 走 comfy-kitchen,
是两个并列后端;我们塌的是 **thu-ml sage 的 sm90 kernel**(pin 的 d1a57a5 已是
main 最新,上游未修)。i2v 节点的 first_frame 走 qwen3vl vision tokens 进
conditioning(不改 latent 形状),序列长度变化触发 kernel 尾块 bug;VAE/宿主机
/音频路径均被对照排除。ck attention 同输入形状实测干净 → kernel 特异性坐实。

**决策**:h3_i2v 走 `--use-ck-attention` 端点 `h3_ck`(comfy-kitchen 0.2.31,
含 #112 修复;384s/$0.51,快过 pytorch 13%,精度最高);t2v 留 thu-ml sage
(253s,t2v 上干净且比 ck 快 46%)。start.sh 以 `USE_CK_ATTENTION=true` 开关
(h3-7 起烤入;此前用 dockerStartCmd sed 注入过渡)。no-sage 端点退役。

**验收补丁**:抽帧看片必须含**尾帧**(此坑首轮 n=0/180/340 三点抽查漏掉)。
帧间差扫尾法:`ffmpeg -sseof -2.5 … rawvideo` 逐帧 MAD,突变 >3×中位即坏。

### sm90 塌坏定位数据(2026-08-20,待上游修复)

进程内抓取(scripts/inject_sage_shape_log.py 注入 attention_sage)的真实调用形状,
全部 `sageattn(q,k,v, tensor_layout="HND", is_causal=False)`,bf16,
q/k/v 是 fused QKV(hidden 21504=3×56×128)的非连续切片视图:

| 流 | shape | stride |
|---|---|---|
| 视频流 t2v 15s/1280×736(净) | (1,56,**100691**,128) | (7168,128,**21504**,1) |
| 视频流 i2v 15s/1280×736(塌) | (1,56,**101509**,128) | 同上 |
| 文本流 i2v | (1,56,943,128) | (7168,128,7168,1) |
| VAE decode | (1,32,1797,64) fp16 | — |

净/塌只差 **+818 keyframe tokens**(i2v 首帧走 qwen3vl vision tokens 进文本流、
keyframe latent tokens 拼进视频流,latent 形状不变——`MiniMaxH3ImageToVideo`
读码证实)。合成探针(scripts/diag_sage_tail.py,随机 bf16 + as_strided 精确
复刻布局,L 到 90k)未复现——触发还需真实 L≈101k 和/或真实数值分布。
issue 草稿:docs/sage-sm90-issue-draft.md,待用户确认后发 thu-ml。
上游修复后:i2v 端点 USE_CK_ATTENTION→USE_SAGE_ATTENTION 即可切回(省 36%)。

## 产物链路

大视频超 RunPod output 上限会被**静默丢弃**(COMPLETED 但 output=None)。
生产配置必须带 R2:template env 配 BUCKET_NAME / BUCKET_ENDPOINT_URL /
BUCKET_ACCESS_KEY_ID / BUCKET_SECRET_ACCESS_KEY,handler 返回 7 天
presigned URL(type: r2_url),CLI 自动下载。

## 分辨率 / 时长

- ResolutionSelector:megapixels + 16:9 + 32 对齐;0.4MP→848×480,0.9MP→1280×736
- duration 按 24fps 折算,帧数对齐 ≡5 (mod 17);15s→362 帧,生成正常
