# MiniMax H3 集成笔记(实测,2026-08-19)

## 推理栈现状

| 组件 | 状态 | 说明 |
|---|---|---|
| ComfyUI v0.33.1 + torch 2.13.0(PyPI 即 cu130) | ✅ | 工作流全部 core 节点,零 custom node |
| comfy-kitchen CUDA 融合量化算子 | ✅ 启用 | cu130 是启用前提(quant_ops.py 在 cu<13 时整体禁用);DiT int8_convrot + TE nvfp4_awq |
| **SageAttention 2.2.0** | ❌ **禁用(输出错乱)** | 见下 |
| gcc(triton 推理期 JIT) | ✅ 必需 | 缺了首次采样报 "Failed to find C compiler" |

## SageAttention 乱码事故(已定罪)

sage 2.2.0(sm_90 源码编译)+ H3 输出为 patch 级马赛克乱码:色调跟随 prompt、
patch 结构存在、空间完全碎裂 —— 典型的 attention 输出静默错乱。同 seed 同配置
唯一变量对照:开 sage 乱码、关 sage 完美。推测与 H3 音视频联合生成的非标准
attention 结构有关(变长/多模态序列),sage 的 int8 QK kernel 不兼容。

**默认 USE_SAGE_ATTENTION=false**。sage 实测加速约 28%(8 步:50.3s vs 69.5s),
但输出错误毫无意义。后续可跟踪 sage/ComfyUI 对 H3 的适配再开。

教训:**管线通 ≠ 内容对**。冒烟验收必须抽帧看画面,不能只看文件生成成功。

## 产物链路

大视频超 RunPod output 上限会被**静默丢弃**(COMPLETED 但 output=None)。
生产配置必须带 R2:template env 配 BUCKET_NAME / BUCKET_ENDPOINT_URL /
BUCKET_ACCESS_KEY_ID / BUCKET_SECRET_ACCESS_KEY,handler 返回 7 天
presigned URL(type: r2_url),CLI 自动下载。

## 分辨率 / 时长

- ResolutionSelector:megapixels + 16:9 + 32 对齐;0.4MP→848×480,0.9MP→1280×736
- duration 按 24fps 折算,帧数对齐 ≡5 (mod 17);15s→362 帧,生成正常
