## SageAttention 乱码事故(已修复,2026-08-19)

**根因不是 sage 与 H3 不兼容,是 v2.2.0 tag 本身的 bug**(与 Modal 侧踩坑同源):
tag 带着 PR #218 的 sm90 wrapper —— custom op 往 out tensor 写结果却没声明
mutates_args,torch functionalization 把写入当 dead store 丢弃,拿到未初始化
显存 → patch 级马赛克,且日志全绿(上游 issue #288/#320)。

**修法:pin main 的 d1a57a546c3d**(2025-12-22 后已修)。同 seed 验收通过,
默认 USE_SAGE_ATTENTION=true。扩 sm89 卡时注意上游 setup.py 共享 NVCC_FLAGS
的缺陷(thu-ml#360):单架构编译会产出假 sm89 kernel,需 per-arch gencode
补丁 + cuobjdump 逐 .so 验证,并在启动侧做 compute_cap ∈ {8.9,9.0} 白名单门控。

教训:**管线通 ≠ 内容对**。换 attention/量化后端必须同 seed 抽帧看片 ——
速度、日志、退出码全都会骗人(坏版跑得也快,因为它确实在算,只是结果被丢)。

## 实测性能(H100,848×480=0.4MP 基准)

| 配置 | execution |
|---|---|
| 5s / 0.4MP / 8 步 LoRA | 无 sage 69.5s → **sage 修复版 41.7s(1.7x)** |
| 15s / 0.9MP(1280×736)/ 20 步 | 无 sage 1032.6s($1.37)→ **sage 修复版 543.9s(1.9x,$0.72)** |

sage 增益随序列长度上升(attention O(n²))。坏版 tag 的 216.8s 不作数
(计算结果被丢弃,输出乱码)。

## 产物链路

大视频超 RunPod output 上限会被**静默丢弃**(COMPLETED 但 output=None)。
生产配置必须带 R2:template env 配 BUCKET_NAME / BUCKET_ENDPOINT_URL /
BUCKET_ACCESS_KEY_ID / BUCKET_SECRET_ACCESS_KEY,handler 返回 7 天
presigned URL(type: r2_url),CLI 自动下载。

## 分辨率 / 时长

- ResolutionSelector:megapixels + 16:9 + 32 对齐;0.4MP→848×480,0.9MP→1280×736
- duration 按 24fps 折算,帧数对齐 ≡5 (mod 17);15s→362 帧,生成正常
